# MNIST Digit Classifier on a Micrograd-Style Autograd Engine

A handwritten-digit classifier built on a small autograd engine written from scratch with NumPy. The engine follows the design of Andrej Karpathy's [micrograd](https://github.com/karpathy/micrograd), and the project was inspired by 3Blue1Brown's video on [Introduction To Neural Networks](https://www.youtube.com/watch?v=aircAruvnKk).

**Result: about 98.2% accuracy on the 10,000-image MNIST test set**, from a 784 → 128 → 64 → 10 network with 109,386 parameters, trained for 12 epochs at roughly 5–10 seconds per epoch on a CPU.

## Dataset

[MNIST](https://github.com/sunsided/mnist) (original page: [yann.lecun.com/exdb/mnist](http://yann.lecun.com/exdb/mnist/)): 70,000 grayscale 28×28 images of handwritten digits, split into 60,000 training and 10,000 test images. It was assembled by Yann LeCun, Corinna Cortes and Christopher Burges. The dataset is not included in this repo.

## How it works

- Every number in the network lives in a `Value` object that remembers which `Value`s it was computed from and how to pass gradients back to them.
- A forward pass builds a graph of these objects. Calling `loss.backward()` walks the graph in reverse and applies the chain rule to get the gradient of every weight (backpropagation).
- A mini-batch gradient-descent loop nudges each weight against its gradient to lower the loss.
- **What differs from micrograd:** each `Value` holds a NumPy array instead of one scalar. A batch of 64 images then produces about 30 graph nodes instead of millions, and each node's math runs in compiled NumPy code. The design is the same, only much faster.

```
MNIST files → data.py load() → train.py loop (augment → forward → loss → backward → update)
            → weights.json → predict.py → test accuracy
```

## Project layout

```
ML_digits/
├── train/          # MNIST training images + labels (IDX files, .gz or unzipped)
├── test/           # MNIST test images + labels
├── nn.py           # Autograd Engine, Layer, MLP
├── data.py         # Loads MNIST, subsamples, standardises, flattens
├── train.py        # Loss, augmentation, training loop, saves weights and history
├── predict.py      # Loads saved weights, evaluates on the test set
├── weights.json    # Trained parameters (generated by train.py)
└── history.json    # Loss and test accuracy per epoch (generated by train.py)
```

## Setup

```bash
python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # macOS / Linux
pip install numpy              # add Pillow only if you load PNG folders instead of IDX files
```

Download MNIST and place the files like this, unzipped or `.gz`:

```
train/   ...images...ubyte   ...labels...ubyte
test/    ...images...ubyte   ...labels...ubyte
```

`data.py` finds the files by looking for "images" and "labels" in their names.

## Usage

**Train**

```bash
python train.py
```

The call at the bottom of `train.py` controls the run:

```python
train(num_train=60000, num_test=10000, epochs=12, learn_rate=0.1, batch=64, hidden=128)
```

Weights and a per-epoch history are saved after every epoch, so `Ctrl+C` at any point still leaves a usable model. Use smaller `num_train` and `num_test` values for a quick trial run.

**Evaluate**

```bash
python predict.py
```

Prints the true label, prediction and confidence for each test image, then the overall accuracy.


## Model and training recipe

| Setting | Value |
|---|---|
| Input | 784 pixels, standardised with `(x − 0.1307) / 0.3081` (Mean and standard deviation provided in datset documentation)|
| Architecture | 784 → 128 → 64 → 10, ReLU on hidden layers, raw logits at the output |
| Parameters | 784·128 + 128 + 128·64 + 64 + 64·10 + 10 = 109,386 |
| Initialisation | Uniform in ±√(6 / nin) (He-style), zero biases |
| Loss | Softmax cross-entropy with label smoothing 0.1 |
| Optimiser | Mini-batch SGD, batch 64, weight decay 1e-4 |
| Learning rate | Cosine decay from 0.1 towards 0.005 over 12 epochs |
| Augmentation | Random shifts of up to 2 pixels to prevent overfitting, training batches only |

## Results

| Run | Test accuracy |
|---|---|
| Scalar micrograd-style, 196 → 32 → 10 (14×14 pooled), 8 epochs | ~95.1% |
| Array version, 784 → 128 → 64 → 10, plain SGD | ~98.0% |
| Plus shift augmentation, weight decay and label smoothing (current) | ~98.2% |

Runs differ by about 0.1–0.2 points because initial weights and augmentation are not seeded.

**Speed.** The first scalar version took about 0.22 s per image, and fusing each neuron's sum into one dot-product node cut that to about 0.0024 s. Switching each `Value` to hold a NumPy array brought a full epoch down to 2–3 seconds (5–10 seconds with augmentation) on a CPU.

## Notes

- `predict.py` must build the same architecture used in training (`MLP(784, [128, 64, 10])`). Weights are loaded with `zip`, which stops at the shorter list, so a mismatched architecture can be misassigned silently.
- `weights.json` from the earlier scalar version is not compatible with the current code. Retrain after pulling the changes.
- If you turn dropout on, call `model.train_mode(False)` before measuring accuracy.
