# Digit Classifier using a Rudimentary Neural Network

A handwritten digit classifier built on a tiny scalar autograd engine, inspired by Andrej Karpathy's [micrograd](https://github.com/karpathy/micrograd) and 3blue1brown's video on [Introduction To Neural Networks](https://www.youtube.com/watch?v=aircAruvnKk). 

**Result: ~95.1% accuracy on the full 10,000 image MNIST test set**, from a 196 input, 32 hidden-unit MLP trained for 8 epochs on all 60,000 training images.

## Working Mechanisms

Each number in the network is a `Value` object that remembers how it was computed. Running a forward pass builds a graph of these objects, and calling `.backward()` on the loss walks the graph in reverse to compute every gradient (backpropagation). A plain gradient-descent loop then nudges every weight against its gradient to minimise the loss function.

### Dataset

Download MNIST(https://github.com/sunsided/mnist) and place them like this, unzipped or `.gz`:

```
train/   ...images...ubyte   ...labels...ubyte
test/    ...images...ubyte    ...labels...ubyte
```

`data.py` finds the files by looking for "images" and "labels" in the file names. The dataset is not included in this repo.

## Usage

**Train**

```bash
python train.py
```

The call at the bottom of `train.py` controls the run:

```python
train(num_train=60000, num_test=10000, epochs=8, learn_rate=0.05, batch=16, hidden=32)
```

Change ```num_train``` and ```num_test``` values to test the model.
Weights and a per-epoch history are saved after every epoch, so `Ctrl+C` at any point still leaves a usable model.

**Evaluate / predict**

```bash
python predict.py
```

This loads `weights.json`, prints the true label, prediction and confidence for each test image, and ends with the overall accuracy.

## Model

| Setting | Value |
|---|---|
| Input | 14×14 = 196 pixels (28×28 images average-pooled 2×2, scaled to 0-1) |
| Hidden layer | 32 neurons, ReLU |
| Output layer | 10 neurons, linear (logits) |
| Loss | Softmax + cross-entropy |
| Optimizer | Mini-batch SGD, batch 16, learning rate 0.05 |
| Parameters | 196·32 + 32 + 32·10 + 10 = 6,634 |

## Results

| Run | Training images | Test accuracy |
|---|---|---|
| Early prototype | 500 | ~80% |
| Mid-size | 10,000 | ~93% |
| **Full dataset** | **60,000** | **~95.1% (10,000 test images)** |

> **Note on `predict.py`:** The model in `predict.py` must match the one used for training exactly: the same architecture (`MLP(196, [32, 10])`) and the same `pool=True` setting in `data.py`. If they differ, the program will not necessarily crash. Because weights are loaded with `zip`, which stops at the shorter list, the parameters can be silently misassigned, and the predictions will be wrong with no error message.

### Speed

The first version, built from scalar `+` and `*` nodes, took about 0.22 s per image. Replacing the per-neuron chain of adds and multiplies with a single fused "dot product" node cut this to about 0.0024 s per image (roughly 90× faster) with identical gradients. A full 60k epoch now takes under 2 minutes.
